# 第 15 期｜BERT：双向 Transformer 的预训练（NAACL 2019）

## 基本信息

- **标题**：BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding
- **作者/机构**：Jacob Devlin, Ming-Wei Chang, Kenton Lee, Kristina Toutanova（Google AI Language）
- **发表**：NAACL-HLT 2019（arXiv:1810.04805v2，2019-05-24）
- **链接**：https://arxiv.org/abs/1810.04805 ｜ 全文 PDF https://arxiv.org/pdf/1810.04805v2
- **代码/预训练权重**：https://github.com/google-research/bert

## 一句话总结

把 Transformer **编码器**堆成深层双向结构，用「随机遮词预测（MLM）+ 下一句预测（NSP）」两个无监督任务在 33 亿词语料上预训练，再对每个下游任务只加一层输出头做端到端微调，在 11 项 NLP 任务上刷新 SOTA——GLUE 80.5（+7.7）、MNLI 86.7（+4.6）、SQuAD v1.1 F1 93.2、SQuAD v2.0 F1 83.1（+5.1）。

## 核心笔记

### 问题 Problem

预训练语言表示有两条路线：**feature-based**（ELMo：把预训练表示当额外特征嗂给任务专用架构）与 **fine-tuning**（OpenAI GPT：整体微调）。两者共享同一个预训练目标——**单向语言模型**——而这正是瓶颈：

- 单向（左→右）意味着每个 token 的自注意力只能看左侧上文，**架构被锁死**；
- 对句子级任务（NLI、paraphrase）次优；对 **token 级任务（问答、序列标注）伤害更大**，因为抽答案时必须同时利用左右两侧上下文；
- ELMo 用「独立训练的左→右 + 右→左两个 LSTM 再拼接」，只是**浅层双向**：每层内部仍单向，且成本翻倍、在 QA 中反向模型无法以问题为条件。

所以核心问题变成：**能不能预训练一个「每一层都真正双向」的 Transformer 表示，而不让模型在预测时偷看自己？**

### 方法 Method

**架构**：多层双向 Transformer 编码器（几乎照搬 Vaswani et al. 2017），记层数 $L$、隐层 $H$、头数 $A$，前馈内层 $4H$。

| 模型 | L | H | A | 参数量 |
| --- | --- | --- | --- | --- |
| BERT-Base | 12 | 768 | 12 | 110M |
| BERT-Large | 24 | 1024 | 16 | 340M |

Base 刻意与 GPT 同尺寸，唯一实质差别是 **attention mask：双向 vs 只看左侧**。

**输入表示**：WordPiece，30k 词表；序列首 token 固定 `[CLS]`（其最终隐状态 $C\in\mathbb{R}^H$ 作句级聚合），句间用 `[SEP]` 分隔，并加**可学习的 A/B 段嵌入**区分两句。每个 token 的输入 = token + segment + position 三种嵌入**逐元素相加**。单序列与句对统一成一条 ≤512 token 的序列。

**预训练任务 1：Masked LM（MLM）**。随机选 15% 的 WordPiece 位置做预测，被选中的位置按 **80% 换成 `[MASK]` / 10% 换成随机词 / 10% 保持不变**；损失只在被遮位置算交叉熵。动机是打破「双向会看到自己」的退化：因为目标词可能被替换或保留，编码器无法判断哪些位置要预测、哪些被换过，只能对每个 token 维持分布式的上下文表示。10%+10% 的设计也缓解「`[MASK]` 在微调时从不出现」的**预训练-微调错配**；随机替换只占全部 token 的 1.5%。

**预训练任务 2：NSP**。每个样本取句 A 与句 B，50% 是真实的下一句（IsNext），50% 是语料里随机一句（NotNext），用 $C$ 做二分类。目的是给 QA/NLI 这类**句间关系**任务补上语言模型本身学不到的信号（最终模型 NSP 准确率 97%–98%）。

**预训练数据与算力**：BooksCorpus 800M 词 + 英文 Wikipedia 2,500M 词 = 3.3B 词（必须用文档级语料而非打散的句级语料，才能抽出长连续序列）。batch 256 序列 × 512 token = 128k token/步，训练 1M 步（≈40 epoch）；Adam，lr 1e-4，前 10k 步 warmup + 线性衰减，dropout 0.1，GELU。为省算力，**90% 的步用序列长度 128，最后 10% 用 512** 学位置嵌入。Base 用 4 个 Cloud TPU Pod（16 芯片），Large 用 16 个 Cloud TPU（64 芯片），**各训练 4 天**。

**微调**：直接换上任务输入输出，**全部参数端到端微调**，新增参数极少。句对任务把 A/B 打包进一条序列，自注意力天然实现「双向交叉注意力」，无需像 BiDAF 那样先各自编码再交叉。输出侧：token 级任务（序列标注、抽取式 QA）用 token 隐状态，句级任务用 $C$。QA 只新增起始/结束两个向量 $S,E\in\mathbb{R}^H$，$P_i=\text{softmax}(S\cdot T_i)$，候选 span 打分 $S\cdot T_i + E\cdot T_j$（$j\ge i$）；SQuAD 2.0 把「无答案」当作 start=end=`[CLS]`，与最佳非空 span 比分数并设阈值 $\tau$。微调极便宜：单卡 Cloud TPU 上 ≤1 小时，SQuAD 约 30 分钟即可到 Dev F1 91.0。

### 效果 Results

**GLUE（Table 1，Test）**：BERT-Large 平均 **82.1**（Base 79.6，OpenAI GPT 75.1，前 SOTA 74.0）；官方榜 GLUE 分数 **80.5 vs GPT 72.8**。逐项：MNLI-m/mm **86.7/85.9**、QQP 72.1、QNLI 92.7、SST-2 94.9、CoLA **60.5**（GPT 45.4）、STS-B 86.5、MRPC 89.3、RTE 70.1。Base 相对前 SOTA 平均 +4.5，Large +7.0。模型越大越好，**在小数据任务上增益尤其明显**。

**SQuAD v1.1（Table 2）**：单模型 Dev F1 90.9；+TriviaQA 预微调后 Test **F1 93.2 / EM 87.4**（7 模型集成），**单模型 91.8 F1 已超过当时榜首集成系统 91.7**；只用 SQuAD 仅掉 0.1–0.4 F1。

**SQuAD v2.0（Table 3）**：单模型 Test **F1 83.1 / EM 80.0**，比此前最佳 +5.1 F1（人类 89.5）。

**SWAG（Table 4）**：Test 86.3，比 ESIM+ELMo（59.2）+27.1，比 GPT（78.0）+8.3（人类专家 85.0）。

**消融（Table 5，Base，Dev）**：

| 变体 | MNLI | QNLI | MRPC | SST-2 | SQuAD F1 |
| --- | --- | --- | --- | --- | --- |
| BERT-Base | 84.4 | 88.4 | 86.7 | 92.7 | 88.5 |
| 去掉 NSP | 83.9 | **84.9** | 86.5 | 92.6 | 87.9 |
| 左→右 + 无 NSP（≈GPT） | 82.1 | 84.3 | **77.5** | 92.1 | **77.8** |
| 上者 + 顶层 BiLSTM | 82.1 | 84.1 | 75.7 | 91.6 | 84.9 |

三个结论：**双向本身值的钱最大**（SQuAD −10.7、MRPC −9.2）；**NSP 主要救 QNLI**（−3.5）；事后加 BiLSTM 能补回 QA 一部分（+7.1）但会拖累 GLUE——说明双向必须在**每一层**都成立，补在顶层没用。

**规模（Table 6）**：3L/768 → MNLI 77.9；24L/1024/16 → 86.6，掩码 LM 困惑度 5.84 → 3.23。即便 MRPC 只有 3,600 条训练样本也严格受益——**充分预训练后，模型变大对小任务依然有效**。

**feature-based 也成立（Table 7，CoNLL-2003 NER）**：微调 BERT-Large Test F1 92.8；冻结后取**最后四层拼接** + 两层 BiLSTM 达 Dev 96.1，仅比全量微调（96.4）低 0.3。

**训练步数与遮罩策略（附录 C）**：1M 步比 500k 步在 MNLI 上多约 1.0；MLM 收敛略慢于 LTR，但绝对精度几乎立刻反超（Fig. 5）。遮罩策略（Table 8）：80/10/10 → MNLI 84.2 / NER 95.4（feature 94.9）；全 `[MASK]` → 84.3 / 94.9 / **94.0**；全随机词 → **83.6** / 94.9 / 94.6。微调对策略不敏感，但 **feature-based 对全 `[MASK]` 明显吃亏**（错配无法被微调吸收）。

### 局限 Limitations

1. **预训练-微调错配仍在**：`[MASK]` 微调时不存在；80/10/10 只是缓解，Table 8 显示 feature-based 场景下错配真实存在（94.9 vs 95.4）。
2. **只预测 15% 的 token**：每步监督信号稀疏，收敛更慢、需要更多步（附录 C.1 承认）。
3. **NSP 的收益有限且可被质疑**：只对 QNLI 显著；论文自己也只在 5.1 给出这一组证据。
4. **只能用 encoder**：没有自回归解码能力，不能做生成；`[CLS]` 未经微调**不是**有意义的句向量（脚注 6）。
5. **512 token 硬上限**，长文档需切分；注意力对长度二次开销。
6. **英文单语**，未做多语言/跟语言。
7. **算力门槛**：4 天 × 64 TPU 芯片；Base 也要 16 芯片。
8. **Large 在小数据上微调不稳定**，靠多次随机重启 + dev 选优（本质是拿 dev 集做选择，存在轻微泄漏风险）。
9. **只验证了 NLU**，未触及生成、检索、结构化预测等更广任务。

## 扩展

### 创新点

- **第一个「深层双向」预训练 + 微调范式**：不是把两个单向模型拼起来（ELMo 的浅层双向），而是靠 MLM 让**每一层**同时看左右。
- **80/10/10 遮罩**：把「预训练有 `[MASK]`、微调没有」的分布错配压到最小，这是工程上最容易被忽略但最实用的一招。
- **统一架构 + 极简任务适配**：句对打包进一条序列，自注意力即双向交叉注意力；每任务只加一个输出头（QA 加两个向量）。
- **证明「规模 + 充分预训练」能反哺极小数据任务**（MRPC 3.6k 样本仍受益），这条结论后来直接支撑了 scaling 叙事。
- **同时验证 fine-tuning 与 feature-based** 两条用法都可用（NER 上只差 0.3 F1）。

### 相关工作

- ELMo（Peters et al. 2018）：feature-based、双层双向 LSTM 拼接。
- OpenAI GPT（Radford et al. 2018）：左→右 Transformer + 微调，是本文最直接的对照组与基线。
- ULMFiT（Howard & Ruder 2018）：判别式微调 + 斜三角学习率。
- Transformer（Vaswani et al. 2017）：架构来源；Cloze task（Taylor 1953）：MLM 的思想源头。
- 与本期序列的关系：第 08 期 Transformer 给了积木，第 15 期 BERT 给了「怎么用无标注数据把积木堆深」；第 14 期 ViT 是同一配方搬到视觉（ViT 用「预测被遮 patch 的像素/离散 token」替代 MLM，且无 NSP）。

### 个人启发

1. **「双向 vs 单向」的选择本质是「任务需要什么信息」**：如果下游只需要前缀（生成、流式），decoder-only 更划算；如果要判句间关系、抽 span，encoder 的双向就是结构性优势。这一点直接解释了今天 LLM 用 decoder-only、而检索/嵌入/分类仍用 encoder 的分工。
2. **MLM 是一个可迁移的「自监督接口」**：换成 patch、图节点、时间序列片断，配方不变——ViT 的 masked patch prediction、后来的 MAE 都是这条线。
3. **遮罩比例与替换策略是超参，不是定理**：80/10/10 + 15% 是经验值，Table 8 说明微调场景下相当鲁棒，但 feature-based 场景要更小心；做自己的预训练实验时，这个表可以直接当 baseline。
4. **微调成本几乎可忽略（≤1 小时）**，说明「贵在预训练、便宜在下游」的经济结构——这是后来 foundation model 商业模式的技术根源。
5. **工程细节值得抄**：90% 步用短序列 + 10% 用长序列学位置嵌入，是长序列预训练省算力的实用技巧。

### 下一步问题

1. **NSP 到底有用吗？** 后续 RoBERTa 等工作去掉 NSP、改动态遮罩后效果更好——说明本文的 NSP 收益可能被「同批次对照不充分」放大。值得回看 RoBERTa（2019）做一次对照。
2. **MLM 的 15% 是不是最优？** 有没有「按难度/按熵」选择遮哪些位置的做法（如 ELECTRA 的替换 token 检测）？
3. **encoder-only 的天花板在哪？** 为什么 2020 年后主流 LLM 转向 decoder-only？差别是在生成能力、训练效率，还是 in-context learning 的涌现？
4. **句向量问题**：`[CLS]` 不微调就不好用，那 Sentence-BERT / 对比学习路线是怎么修的？
5. **中文/多语言**：WordPiece 30k 词表对中文分词是否吃亏？多语言 BERT 的迁移规律如何？

## 术语速查

| 术语 | 含义 |
| --- | --- |
| MLM（Masked Language Model） | 随机遮词并预测原词，使每层可双向建模 |
| NSP（Next Sentence Prediction） | 判断 B 是否为 A 的真实下一句 |
| WordPiece | 子词切分算法，30k 词表，未登录词拆成 `##` 片段 |
| `[CLS]` / `[SEP]` | 序列聚合位 / 句间分隔符，均为可学习嵌入 |
| segment embedding | 标记 token 属于句 A 还是句 B 的可学习向量 |
| feature-based vs fine-tuning | 冻结表示当特征 vs 全参数微调 |
| 预训练-微调错配（mismatch） | 预训练见 `[MASK]`、微调不见导致的分布差异 |
